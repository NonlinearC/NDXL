typedef int(*) NDXLVertexCallback(NDXLVertex *_Vertex, double *_Y, double _Time, void *_Params)

Defines a user-supplied discrete callback that is invoked during simulation of the vertex's host network.

Parameters
[in]_VertexThe calling vertex.
[in,out]_YFlat vector containing the most recently accepted state vector of the calling vertex. Is guaranteed to have ndxlGetVertexOrder(calling_vertex) elements, and may be modified in-place.
[in]_TimeCurrent simulation time of the calling vertex, equivalent to ndxlGetVertexTime(calling_vertex).
[in]_ParamsUser-defined parameters associated with the calling vertex.
Returns
Integer indicating function success (zero) or failure (any nonzero value).
Note
If this function returns a nonzero value during simulation, NDXL terminates the simulation, and internally raises a NDXL_SIM_ERR.
Warning
Writing beyond ndxlGetVertexOrder(calling_vertex) elements to the state vector can result in out-of-bounds writes and undefined behaviour.

◆ NDXLVertexDynamics

typedef int(*) NDXLVertexDynamics(NDXLVertex *_Vertex, double *_dY, const double *_Y, double _Time, void *_Params)

Defines a user-supplied function that governs how the state of a vertex evolves over time.

Parameters
[in]_VertexThe calling vertex.
[out]_dYFlat output vector containing the time derivative of the calling vertex. ndxlGetVertexOrder(calling_vertex) total elements must be written to it, even if those elements are zero.
[in]_YFlat input vector containing the current Runge-Kutta stage of the calling vertex. Is guaranteed to have ndxlGetVertexOrder(calling_vertex) elements.
[in]_TimeLocal simulation time of the calling vertex, offset by a fraction of the step size corresponding to the next Runge-Kutta stage. Note that this is generally NOT equivalent to ndxlGetVertexTime(calling_vertex), which only updates on a successful step.
[in]_ParamsUser-defined parameters associated with the calling vertex.
Returns
Integer indicating function success (zero) or failure (any nonzero value).
Note
If this function returns a nonzero value during simulation, NDXL terminates the simulation, and internally raises a NDXL_SIM_ERR.
Warning
The function does not verify the number of elements written to the output array. Not writing to each element can result in garbage values or stale states being propagated. Writing beyond ndxlGetVertexOrder(calling_vertex) elements can result in out-of-bounds writes and undefined behaviour.
See also
ndxlGetVertexOrder

◆ NDXLVertexNoise

typedef int(*) NDXLVertexNoise(NDXLVertex *_Vertex, double *_dG, const double *_Y, double _Time, void *_Params)

Defines a user-supplied function that provides the amplitude of noise, for each element in its state vector, for each independent Wiener process the vertex is driven by.

Parameters
[in]_VertexThe calling vertex.
[out]_dGFlat output matrix containing the noise amplitudes, where element ij (at index i * ndxlGetVertexChannelCount(calling_vertex) + j) represents the amplitude of the j-th Wiener process on the i-th state-vector element. ndxlGetVertexOrder(calling_vertex) x ndxlGetVertexChannelCount(calling_vertex) total elements must be written to it, even if those elements are zero.
[in]_YFlat input vector containing the current Runge-Kutta stage of the calling vertex. Is guaranteed to have ndxlGetVertexOrder(calling_vertex) elements.
[in]_TimeLocal simulation time of the calling vertex, offset by a fraction of the step size corresponding to the next Runge-Kutta stage. Note that this is generally NOT equivalent to ndxlGetVertexTime(calling_vertex), which only updates on a successful step.
[in]_ParamsUser-defined parameters associated with the calling vertex.
Returns
Integer indicating function success (zero) or failure (any nonzero value).
Note
If this function returns a nonzero value during simulation, NDXL terminates the simulation, and internally raises a NDXL_SIM_ERR.
Warning
The function does not verify the number of elements written to the output array. Not writing to each element can result in garbage values or stale states being propagated. Writing beyond ndxlGetVertexOrder(calling_vertex) x ndxlGetVertexChannelCount(calling_vertex) elements can result in out-of-bounds writes and undefined behaviour.
