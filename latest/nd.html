Network Dynamics

This page is dedicated to terminology pertaining to "network dynamics" in general, as well as how certain concepts are implemented/interpreted in NDXL.

What is Meant by "State Vector"?

An agent's state vector is the vector of time-dependent properties that fully describe the agent. Because a scalar can be represented as a unit-length array, NDXL treats all state vectors as arrays, allowing for multidimensional dynamics to be evaluated by default: the time derivative for each element is just written in-place to the output array similar to the Getting Started example. In a power grid modelled by the swing equation, for example, each node has two states, namely, its phase angle \(\theta\) and frequency \(\omega\), while each transmission line is typically only described by its coupling constant \(A\). We can explicitly write the state vector of node \(i\) as:

\[ \vec{x}_i = \left\langle\theta_i,~\omega_i\right\rangle \]

And similarly the state vector of edge \(ij\) is:

\[ \vec{y}_{ij} = \left\langle A_{ij}\right\rangle \]

Do all elements of a state vector change over time?

They can, but they do not necessarily have to. An element constant with respect to time is called a static element, and if all elements of an agent's state vector are static, then the agent itself is said to be a static agent. Static elements in NDXL are characterised by a return value of \(0\) for that element in its dynamics function; static agents can be simply assinged NULL for their dynamics.

What if agent dynamics depend on constants in the equation?

Suppose the dynamics of a vertex are given by

\[ \frac{d\vec{x}}{dt} = Ct + D\vec{x} \]

where \(C\) and \(D\) are constants. In the agent's constructor, these numbers are passed using the void* params argument, which is always the last argument in a constructor. During dynamics evaluation, they can be extracted by converting the void* params to whatever datatype the constants initially were defined as, as shown in the Getting Started example.

Heterogeneous Dynamics

It is common to express the dynamics of network agents as a single function according to which each agent's state vector evolves, and have their state vectors and void* params refer to parameters. In the Kuramoto model, for example, each vertex has a unit state vector containing its phase \(\theta\), with its void* params containing its eigenfrequency, and evolves according to the agentic Kuramoto model. In the swing equation, each vertex has a two-component state vector containing its phase \(\theta\) and frequency \(\omega\), and evolves according to the swing equation. There is, however, no strict requirement saying agents must:

  • Have identically cardinal state vectors
  • Depend on the same time-variant parameters as others
  • Evolve according to the same dynamics, noise, or discrete callback functions
  • Be influenced by the same noise channels and/or to the same degree
  • Share user-defined void* params (constants)
  • Have the same initial conditions

Whenever one or more of the first four conditions is false, the agents are said to be heterogeneous (initial conditions and constants are usually unique by default). This gives rise to the term "heterogeneous dynamics", simply meaning that two or more agents in the network do not exhibit common dynamics. This can be, for example:

  • One node evolving according to the Kuramoto model, its neighbour to the swing equation
  • One node being static, its neighbour dynamic
  • One node being stochastic, its neighbour purely deterministic
  • One node having a ten-element state vector, its neighbour a scalar state
  • One node being influenced by noise channels \(1\), \(3\), and \(6\), its neighbour by channels \(2\) and \(5\)

NDXL makes simulating heterogeneous dynamics easy by assigning agent properties directly to the agents themselves, as outlined in the Heterogeneous Dynamics example.

Stochasticity

The default network dynamics equations are written as purely deterministic ODEs, however, some systems exhibit random fluctuations in the differential equation signal. These fluctuations are called noise, and add an element of stochasticity to the system, transforming the governing dynamics from an ODE to an SDE (stochastic differential equation). The stochastic contributions are assumed to follow Brownian motion, and the random path taken from start to finish is called a Wiener process. This process is further documented in the Stochasticity examples.

Delays

A delay is a concept in information theory that pertains to the time \(\tau\) taken for information to travel from point A to point B. In the context of network dynamics, and specifically under the physical interpretation of a network, "delays" refer to the time taken for a signal to propagate from one vertex to its neighbour along a given edge. NDXL therefore treats delays as explicit edge properties, and each edge is responsible for mediating delayed interactions between the vertices it connects. The memory and implications are documented in edge creation, while the mathematical details are further explained in the Delays examples.

Higher-Order Dynamics

The descriptions of differential equations governing agent dynamics have thus far (Dynamics and Stochasticity) been of first-order: \(\frac{d\vec{x}}{dt}\). Of course, many systems exhibit higher-order dynamics, written as \(\frac{d^n\vec{x}}{dt^n}\). To solve these systems using the first-order solvers, we must rewrite the \(n^{th}\)-order equation as a set of \(n\) coupled first-order equations by using a substitution of variables. The state vector of the agent then goes from having one element to \(n\) elements, where the derivative of the \(i^{th}\) component is used to compute the derivative of the \((i+1)^{th}\) component. This process is further detailed in the Higher-Order Dynamics examples.

Dynamic Topologies

The size, order, and topology are usually fixed for a given network i.e., once the network is created, these variables cannot - and do not - change. For some applications and models, this approach is sufficient. However, there also exist networks for which these variables are not constant (see the examples listed in the introduction); in these cases, "dead" agents are usually simulated by zeroing their contributions to the overall dynamics, and "new" agents are simulated by reserving space before the simulation for their eventual existence. This wastes computational resources, and also provides a hard limit on the amount of new agents that can be brought into the network. Simulating these kinds of networks is specifically what NDXL was designed for: by allowing agents to be created and destroyed during simulation, only ever those that are still part of the network are actually simulated. See Simulating Networks With Dynamic Topologies for details how to simulate dynamic topology networks, what the rules are for when and how to add/remove/rearrange agents, and what the limitations, mathematical implications, and performance impacts are.
