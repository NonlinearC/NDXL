Introduction

What is NDXL?

NDXL is a cross-platform and programming language-independent package for simulating complex network dynamics, with an emphasis on dynamic topologies. What this simply means is:

  • NDXL can be used on Windows, Linux, and x86-64 macOS
  • It can be integrated into any programming language capable of interfacing with compiled C libraries
  • It facilitates simulation of networks whose number and arrangement of vertices and edges change over time
  • It supports a wide range of network structures and systems of differential equations, including ordinary, delayed, and stochastic dynamics

Why use NDXL?

A wide variety of scientific disciplines rely on network-based modelling to simulate complex systems composed of interacting, potentially heterogeneous components. These include, but are not limited to:

  • Physics/chemistry: gas-particle ensembles, solid atomic lattices, many-body problem
  • Engineering: power grids, oscillator networks, heat flow, Josephson junctions
  • Biology: predator-prey communities, algal clusters, viral infection
  • Sociology: follower networks, friend groups
  • Information technology: client-server interactions, internet of things

These networks often exhibit behaviour which is difficult/impossible to capture in most other simulation software, for example:

  • A power grid with generators and loads constantly being added/removed
  • An individual-based ecological model in which organisms reproduce, die, and interact with a changing population
  • A computer network with servers going up/down and clients connecting/disconnecting
  • An ensemble of gas particles that slowly leak into the environment

NDXL makes simulating these easy, as vertices and edges can be added to/removed from/changed in the network while a simulation is running. This process is detailed in the Dynamic Topologies section.

Unfortunately, supporting dynamic topologies introduces additional computational and memory-management overhead compared with implementations designed exclusively for static networks. NDXL is continuously being optimised to minimise this overhead.

FAQ

How do I use NDXL from other programming languages?

Through language-specific bindings that expose NDXL's compiled C library to the target programming language. For example, the official Python version is available on PyPI here. Future work on NDXL will involve creating language-specific bindings for other languages like Julia.

Can I write my own language-specific wrappers?

Of course! This is one of the intended uses of the API, and why it was written in C using only the C standard library, primitive, and opaque types. For a detailed guide on how to import NDXL into another programming language (using the Python version as an example), see Cross-Language Interoperability.

Should I use NDXL from C?

Situationally.

The API is designed to provide the user with as much control as possible over the underlying mechanics of the network. Because the C API exposes many configuration parameters directly, constructing and configuring objects can become rather verbose, particularly when many optional parameters are set to 0 or NULL. Languages with features such as default arguments and function overloading can provide more convenient interfaces to the same underlying functionality. This is why the library is also designed with cross-language interoperability in mind - it is much easier, from a user perspective, to use the Python version, for example. With that said, language-specific wrappers can introduce their own significant amount of overhead, depending on how many inter-language translations need to be done during simulation.

A general rule of thumb would therefore be:

  • Use C when performance is important e.g., simulating a 107 node algal cluster.
  • Use another language wrapper if the simulation is small and convenience matters more than control.

What kinds of networks can NDXL simulate?

Almost everything.

There are certain classes of differential equation that NDXL does not directly support (yet), for example, differential algebraic equations (DAEs). NDXL requires the dynamics to be in a standard ODE/DDE/SDE form (see Network Simulation). So, if the conditions of the differential equation allow the network dynamics can be transformed into an ODE/DDE/SDE, then NDXL can simulate the network.

There are also certain solvers that NDXL does not directly support (yet), such as implicit stochastic solvers. The available explicit stochastic methods may be inefficient or unsuitable for certain stiff stochastic systems, for which implicit methods would be more appropriate.

So, it is often more a case of "some networks might be more difficult to solve than others", and this is something we intend to tackle in future updates.
